# ST5: ограниченная дооптимизация обучения L1

Зафиксировано до новых fit, 29 сентября 2026. Пользователь попросил внимательно проверить гиперпараметры и дооптимизировать перспективную модель. Исходная серия ST5 остаётся неизменным историческим контролем; это отдельная серия разработки, не оценка нового метода.

## Основание и конкретные гипотезы

В первой серии менялся только LR LoRA (2e-4 и 5e-5); новая голова в обоих случаях обучалась с LR 1e-3. У base train loss падает 1.0603→0.0067, dev CE минимальна на эпохе 4 (0.8041), а выбранная по F1 эпоха 13 имеет CE 1.2955 при F1 0.6888. Это оставляет непроверенными скорость головы и регуляризацию. Дополнительные эпохи зрелого checkpoint не являются выбранным способом лечения такого переобучения.

Проверяются три направления: меньший LR головы; label smoothing; dropout головы. Label smoothing смешивает однозначную ролевую метку с равномерным распределением: q=(1−ε)·onehot(y)+ε/3. При ε=0.1 истинная роль получает 0.9333, каждая другая —0.0333. Это регуляризация обучающей цели, не утверждение, что люди так голосовали, и не изменение исходной разметки. Dev/test-метрики всегда используют первоначальные индивидуальные ответы без сглаживания.

Основание гипотезы о переуверенности — измеренные кривые ST5 и [Müller et al., NeurIPS 2019](https://proceedings.neurips.cc/paper/2019/hash/f1748d6b0fd9d439f71450117eba2725-Abstract.html). В этой работе наблюдалось улучшение калибровки в исследованных задачах, но также изменение структуры представлений и ограничения для дистилляции. Поэтому её выводы не гарантируют полезность вероятностей ролей для будущего обмена KuKi. Реализация — `torch.nn.functional.cross_entropy(label_smoothing=ε)` установленного PyTorch; формула и градиенты проверяются отдельным тестом.

Первые три новых fit завершают согласованную таблицу Head LR×Smoothing с историческим base; dropout проверяет отдельное изменение. Условия выбраны до результатов, дополнительных trial и адаптивного расширения сетки нет. Четырёх точек недостаточно для обоснованного многомерного TPE-поиска, поэтому Optuna здесь не используется как имитация полноценной оптимизации. Преимущество конкретных значений не предполагается.

Архитектура, rank8/alpha16, LoRA dropout0.1, weight decay0.01, batch8, окна1024/overlap128, warmup34 и линейный спад, исходная инициализация и порядок статей совпадают с base. Dropout относится к новой голове, не к LoRA. Каждая модель начинает с закреплённой предобученной базы и новых LoRA/head: без продолжения переобученного ST5 checkpoint. По 20 эпох / 340 updates / 2700 предъявлений. Seed42, прежнее разбиение 145/31/31; фактически 135 активных train и29 dev статей. Новых данных/seed/архитектур нет. Пустые L1 маскируются, нормировка по ответам и статьям прежняя. Итоговый test закрыт.

## Бюджет и сохранение

Отдельный предел3000с (50минут) всех GPU-процессов: не более650с на fit,120с на техническую проверку и180с на replay. Суммарный лимит имеет приоритет. Четыре fit, общий максимум1360updates/10800предъявлений; технические шаги отдельно. Остановка train за60с до лимита для оценки/сохранения; при ранней остановке фиксировать выполненный объём. Не исключать медленный или неудачный trial из отчёта.

Checkpoints best-F1, last и дополнительно best-CE; сохраняются optimizer/scheduler/RNG/порядок/позиция и полное происхождение. Checkpoint best-CE — диагностический выход заранее выбранного второго критерия, не скрытая замена основного. Разные smoothed/unsmoothed train-loss нельзя напрямую сравнивать как одинаковую CE. Оценочная CE всегда обычная. Исходные файлы первой серии, код модели и её конфигурации не меняются; новые расширения лежат в search/.

## Выбор и интерпретация

В каждом fit основной checkpoint: максимум прежнего dev macro-F1 с весами статей, затем минимум CE, затем ранняя эпоха. Основная метрика остаётся прежней. Для всех вариантов сообщаются также обычный F1, каждый класс, accuracy, CE и Brier, train/dev разрыв и last. Исторический base включён в таблицу наравне с новыми best.

Рекомендуемая замена base требует Δmacro-F1≥+0.01, CE≤1.295540692180844 и Brier≤0.1572 (для точного сравнения использовать полное значение из исходного JSON). Из прошедших ограничение выбирается максимальный F1, затем меньшая CE. Это инженерное правило разработки, не статистический тест. Абсолютный максимум F1 показывается даже если не проходит ограничения; исходный base сохраняется, если подходящей замены нет.

Отдельно допускается сохранить вариант для дальнейшей проверки вероятностей: F1 не ниже base−0.01, CE меньше base хотя бы на0.10 и Brier не хуже base. Выбор среди них по CE, затем F1. Он не объявляется лучше по классификации или гарантированно калиброванным. Temperature scaling и дополнительные настройки на dev в эту серию не входят.

Описательные парные bootstrap-интервалы разностей выбранных прогнозов с base строятся по группам статей,2000повторов,seed42. Они не учитывают выбор модели/эпох и изменчивость обучения. 29 многократно использованных dev-статей ограничивают доказательность; для научного вывода остаётся закрытый итоговый test после фиксации метода.

## Проверки

До fit: тест ε=0 на точное совпадение с исходной loss; формула ε=0.1 и градиенты с индивидуальными весами; маскирование пустых ответов. GPU: фактическое обновление активных модулей, неизменность базы, точное восстановление следующего update для сглаженной цели, одинаковый hash начальных параметров с исходной серией.

После fit: свежие загрузки best-F1 train/dev, best-CE dev и last dev всех четырёх моделей; независимые метрики из JSONL; replay старого base в новой обёртке. Сравнить сохранность всех прежних артефактов ST5 и ST0–ST4, отдельно проверить self-review. Изменение качества не разрешает автоматически запускать ST6.
