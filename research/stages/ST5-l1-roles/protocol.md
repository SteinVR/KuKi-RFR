# ST5: самостоятельные роли заданных упоминаний

Зафиксирован 29 сентября 2026 до первого fit по поручению пользователя начать ST5. Задача — получить проверенный самостоятельный L1 и разобрать его ошибки. ST6 и новые ST4-серии не входят в этот запуск.

## Данные и область вывода

Прежний ST0 split 145/31/31, seed 42. Только train/dev через `load_development`; test не токенизируется, не оценивается и не участвует в диагностике. Совместный производный файл читается и хешируется для проверки целостности. Только русский KuKi, без новых разметок и внешних данных.

В train 135 статей с L1, 1234 индивидуальные отметки (309/668/257 в порядке PROTAGONIST/ANTAGONIST/INNOCENT); dev 29 статей, 200 отметок (46/112/42). Пустые L1-ответы маскируются, 10 train и 2 dev статьи без L1 исключаются из этой условной задачи. Это не отрицательные или нейтральные примеры. ST0 уже удалил точные дубликаты и замаскировал конфликтующие роли одного упоминания внутри одного ответа. Разные роли разных разметчиков сохраняются: 13 спорных точных позиций train, 0 dev. Ответы разных людей не объединяются голосованием.

Позиции упоминаний задаются человеком. Отсутствующие упоминания не порождают отрицательные примеры. Автоматическое обнаружение участников, кореференция и нейтральный класс не проверяются. При одинаковой статье и позиции модель выдаёт один прогноз независимо от разметчика.

## Модель и обучение

Чистый закреплённый RuModernBERT-base, новые LoRA rank8/alpha16/dropout0.1 и новая голова. Никаких весов ST1–ST4. Окна1024 с перекрытием128, веса повторных токенов суммируются в1. BF16-база, FP32 LoRA/головы, FlashAttention2, без gradient checkpointing; закреплённая среда uv без обновлений.

Проверенное символьное представление ST2 переиспользуется как код, без его весов: проекция токенов в64 измерения, признаки двух границ с символьной геометрией, среднее внутри заданного упоминания, среднее по символьным позициям всей статьи и log-длина. Контекст статьи — среднее соответствующих символьным позициям контекстных токенов, не дополнительный проход. MLP с64 скрытыми измерениями, dropout0.1, softmax на3 роли. Наследуемая голова предложений границ заморожена и не используется в классификации. Точные входные координаты сохраняются, включая пробельные и внутритокенные границы; границы между окнами не обрезают упоминания.

Cross-entropy: среднее по упоминаниям в ответе, затем по непустым ответам статьи, затем по статьям. Дополнительных весов классов нет. Статьи без L1 не обучаются. Все активные статьи показываются20 раз:2700 предъявлений,340 optimizer updates (накопление8 статей, последний пакет7). AdamW decay0.01, clip1, warmup34 updates, линейный спад к0.

Конечная матрица: `base` adapter LR2e-4 и `low-lr` LR5e-5; head LR1e-3 в обеих. Одинаковые начальные веса, порядок статей, seed42, предел20 эпох/340updates. Подбор других конфигураций не предусмотрен. Бюджет всей серии1800с процессов сGPU, включая preflight и replay; не более750с на каждый fit, оставшиеся300с на проверки. Остановка обучения за60с до индивидуального лимита для финальной оценки и сохранения. Время подготовки кода и CPU-baselines учитывается отдельно. Пауза сохраняет optimizer/scheduler/RNG/порядок/позицию на границе update; продолжение не сбрасывает исторический бюджет.

## Контроли и выбор

Два CPU-контроля: частоты ролей train с той же нормировкой и word(1–2)+char_wb(3–5) TF-IDF logistic C10, max_iter1000, без поиска. Текст контроля — упоминание и ±200 символов контекста, TF-IDF обучается только на train. Sample weights сохраняют равный вес статей (сумма135). Это ориентир исходного качества, не контроль, отделяющий вклад полного контекста или архитектуры.

Основной macro-F1 — среднее F1 трёх классов по матрице ошибок, взвешенной как обучающая цель: упоминания→непустые ответы→статьи. Дополнительно обычный macro-F1 по индивидуальным отметкам, F1/precision/recall каждого класса, обычная и взвешенная accuracy, cross-entropy/Brier. Отсутствующий в диагностическом срезе класс имеет F1=0; размер среза обязателен. Argmax, фиксированный порядок ничьих PROTAGONIST/ANTAGONIST/INNOCENT; порогов нет.

Checkpoint выбирается по максимальному dev macro-F1; равенство разрешается меньшей cross-entropy, затем более ранней эпохой. Между двумя fit то же правило, при полном равенстве первый base. Last сохраняется отдельно. Успех разработки: проверенная реализация, полные артефакты и понятное исходное качество, а не обязательное улучшение заданной величины. Практический ориентир преимущества над TF-IDF — Δmacro-F1≥0.02; это не тест статистической значимости и не критерий автоматического запуска ST6.

## Проверки и анализ

До fit: нормировка и маскирование, границы/пересечения/пустые ответы, конечные градиенты, фактическое обновление LoRA и головы, неизменность базы; точное восстановление следующего update вместе с optimizer/scheduler. Профиль включает самую длинную активную train-статью.

После: свежая загрузка двух best и last, воспроизведение train/dev прогнозов, независимый пересчёт метрик из JSONL. Диагностика: матрица ошибок, ошибки по ролям, источникам и совпадению строки упоминания с train, несколько уверенных ошибок с контекстом. Формулировки причин отделяются от измеренных фактов; новых ручных меток нет. Парный bootstrap по группам статей dev (2000 повторов, seed42) даёт описательный интервал разности с TF-IDF; он не учитывает поиск эпох/LR и изменчивость обучения. Один seed,29 размеченных dev-статей и многократно использованный dev не позволяют заявить независимое обобщение.
