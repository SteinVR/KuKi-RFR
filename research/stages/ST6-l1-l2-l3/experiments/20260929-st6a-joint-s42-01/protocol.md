# ST6-A: общий энкодер L1–L2, независимые выходы

Зафиксировано 29 сентября 2026 **до обучения** по поручению пользователя и решению
организаторского треда `01a0ec92-c8e6-7f52-8d7f-a18f78b450d3`.
Проверяем, помогает ли совместное обучение ролей и фреймов без существенного ущерба
второй задаче. Это первая часть ST6; L3 и явные сообщения в эту серию не входят.

## Исходная точка и контроли

Фиксированный сильный ориентир L1 — ST5 search dropout0.3, best-F1 epoch16,
`20260929-l1-search-dropout-s42-01/checkpoints/best.pt`, dev macro-F1
0.7656171656656019. Сохраняем хеш весов и метрик в `references.json`; последующие
результаты настройки ST5 не меняют этот выбор.

Один новый совместный запуск начинается от закреплённой предобученной базы с новыми
LoRA и головами, **не** от дообученного ST5. Архитектура и настройки L1 взяты
из выбранной конфигурации ST5: mean/context/границы упоминания, dim64,
dropout0.3, smoothing0, LoRA LR2e-4, head LR1e-3, decay0.01,
rank8/alpha16/LoRA dropout0.1, окна1024/overlap128. L2 — среднее токенов
полного документа с компенсацией перекрытий и линейный выход14.
Один энкодер обрабатывает статью один раз; выходы не получают прогнозов друг друга.

Матрица без поиска: **один joint** с весами задач1:1. Готовые отдельные модели
переиспользуются: выбранный L1 ST5 и L2-only ST3 epoch8, Brier0.14892010558080038.
Начальная L1-голова и LoRA берутся из **нулевого** start.pt выбранного ST5,
L2-голова — из нулевого start.pt ST3 l2-only. Одинаковость начальной LoRA
проверяется побайтно. Это сохранённая случайная инициализация, а не перенос
дообученных весов. Dropout головы L1 изолирован от RNG энкодера; начальный RNG
для совместной серии совпадает с ST3 l2-only. Техническая проверка повторяет
один шаг L2-only в старой и новой обёртках и требует точного совпадения параметров.
Новых самостоятельных обучений в этой серии нет.

## Данные, веса и бюджет

Прежнее разбиение ST0:145train/31dev; test закрыт. L1:135 активных train,
29dev,1234/200 индивидуальных отметок. Каждая эпоха проходит все145train:
отсутствие ролей маскируется, а не превращается в отрицательный класс.
L1 loss = среднее по упоминаниям, затем по непустым ответам статьи.
При усреднении по всем145 статьям множитель145/135 сохраняет вес средней
активной статьи. L2 loss = BCE, среднее по14фреймам и индивидуальным ответам.
В joint складываются эти две нормированные цели. Клиппирование общего градиента1.
Неактивный слой не получает градиента; пустой наблюдаемый L1 даёт нулевой градиент.

Единственный fit:20эпох,380updates,batch8статей с фактическим размером последнего
накопления, warmup38, linear decay,2900предъявлений статей; L1 имеет2700
предъявлений с метками. Совместная модель проходит все145статей. Лимит900с на процесс обучения,
1500с на серию включая технические GPU-проверки, загрузки и replay.
Технические шаги учитываются отдельно. Предел технических проверок300с и replay300с.

Исторический ST5 имел340updates и иной порядок135статей. Число предъявлений
размеченных статей совпадает (2700), но общая адаптация/расписание и смешение
батчей отличаются. Сравнение L1 показывает разность готовых систем, не чистый
причинный эффект совместного обучения при одинаковых updates. Дополнительный
L1-контроль не запускается автоматически. Для L2 совпадают начальные веса,
порядок145статей,380updates, LR и расписание; отличие — дополнительная цель L1.
Это осознанно ограниченная серия при дефиците времени, а не заявление о полном
совпадении всех условий исторического L1 и joint. Оба контроля ранее имели
по20эпох выбора на dev. Сохраняются также метрики финальных состояний.

## Выбор одного состояния и критерий результата

Готовые контроли остаются выбранными по своим прежним правилам: L1 — maximum
article-balanced macro-F1, L2 — minimum article-balanced Brier. **До joint fit**
фиксируем `references.json`: F_ref=0.7656171656656019; B_ref=0.14892010558080038.
Хеши исходных метрик, прогнозов, нулевых и выбранных весов сохраняются.

Для каждого joint checkpoint: g1=(F1−F_ref)/0.01;
g2=(B_ref−Brier)/0.003. Выбор лексикографически по
`(min(g1,g2), g1+g2, -L1_CE)`; при полном равенстве остаётся ранняя эпоха.
То есть сначала улучшаем худшую из двух нормированных разностей. Оба выхода
обязательно берутся из одного состояния, отдельно лучшие эпохи не склеиваются.

Положительный инженерный результат требует одновременно g1≥−1 и g2≥−1,
а также хотя бы одного g≥1: потеря L1 не более0.01, рост Brier не более0.003,
и улучшение хотя бы одной задачи на соответствующий шаг. Проверяем также
отдельные роли, фреймы, CE, уверенные ошибки, train–dev разрыв. Если правило
не выполнено, сообщаем отрицательный/компромиссный результат и сохраняем
выбранное диагностическое состояние. Пороги — заранее принятые практические
допуски, **не** статистическая значимость или клиническая non-inferiority.
Дескриптивный парный bootstrap по группам статей2000повторов, seed42,
не учитывает многократный выбор на dev и случайность обучения.

## Проверки и границы вывода

До fit: CPU-тесты целей/масок/отсутствия обмена/правила выбора; на GPU
совпадение L1-прогнозов со старой архитектурой при одинаковых весах,
совпадение начальных общих весов и один точный шаг L2-контроля, изменение LoRAA/B и активных голов,
неизменность базы, точное возобновление следующего update и optimizer,
работа на статьях без L1. После fit: fresh-process replay best train/dev
и last dev, независимый пересчёт основных метрик, хеши кода/входов/весов,
проверка отсутствия test в токенизации/обучении/оценке.

L1 получает заданные человеком позиции ролевых упоминаний. L2 при применении
является функцией только текста: позиции, роли и число упоминаний вообще
не входят в его вычисление. Поэтому контроль «те же позиции без ролей»
здесь структурно совпадает с L2-only; отдельный дублирующий fit не нужен.
Это не снимает такого контроля для будущего явного обмена.
Один seed и многократно использованные31/29dev-статей ограничивают вывод.
Test, трёхзадачная модель, PCGrad и дальнейшая настройка не запускаются автоматически.
