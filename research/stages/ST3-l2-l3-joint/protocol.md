# ST3 — протокол до обучения

29 сентября 2026. Пользователь прямо поручил начать ST3 после перечитывания текущей задачи. Предыдущая остановка относилась к завершённой проверке отрицательных кандидатов ST2.

## Вопрос и границы

Помогает ли L3-разметка фреймам L2 через общий текстовый энкодер без передачи прогнозов? Сохраняем разделение генерации и классификации фрагментов, принятое в этой задаче. Фиксированный GlobalPointer из E3 предлагает top500; общий RuModernBERT+LoRA обслуживает L2 и условный классификатор семейств L3 из E1. Детектор не дообучается и не входит в общий энкодер. Таким образом проверяется перенос **классификационного L3-сигнала**, а не совместное обучение локализации. Это осознанное уточнение устаревшего README, предлагавшего исходный hard-negative ST2.

L2 получает только усреднённые представления текста; координаты, семейства и оценки L3 не входят в его forward. Для обучения L3 предоставляются человеческие фрагменты отдельно по ответам. При автоматической оценке используются исключительно сохранённые прогнозы детектора. Условная оценка с человеческими границами хранится отдельно от автоматической. Низкое качество сквозного L3 не является заранее установленным запретом на проверку вспомогательного обучения.

## Матрица и ресурсы

Ровно четыре обучения со свежими одинаково инициализированными общими параметрами, seed42, без продолжения ST1/ST2:

| Условие | L2 вес | L3 вес | Максимум эпох / обновлений / предъявлений статьи |
|---|---:|---:|---:|
| l2-only | 1 | 0 | 20 / 380 / 2900 |
| l3-only | 0 | 1 | 20 / 380 / 2900 |
| joint025 | 1 | 0,25 | 20 / 380 / 2900 |
| joint100 | 1 | 1 | 20 / 380 / 2900 |

Все используют один порядок 145 train-статей по эпохам и accumulation8; последний блок делится на фактический размер. В L3 участвуют 129 статей с непустыми ответами: 2580 предъявлений с L3-метками за 20 эпох. На остальных L3-ошибка равна нулю; пустые ответы исключаются из условной ошибки. Это не превращает отсутствие отметок в надёжные отрицательные. Лимит обновлений и расписание общие; стоимость FLOPs не одинаковая. Исторический E1 обучался на 129 статьях без этих нулевых предъявлений, поэтому основные контроли новые.

Основной предел серии — 3600 секунд процессов с GPU, включая профиль, проверки, обучение и восстановление. Профиль/технические проверки до 120 секунд, каждое обучение до 750 секунд, финальная проверка до 240 секунд; остаётся резерв 240 секунд на техническую неисправность, без добавления гиперпараметров. Ожидаемая стоимость до профиля — 4×450–650 секунд, всего около 35–45 минут; это оценка, не измерение. При превышении бюджета сохраняется неполный результат; лимит не расширяется. Профиль нужен до полноразмерного запуска; если стоимость не позволяет матрицу, изменение общего числа эпох фиксируется до первого fit. Ранней остановки по dev нет, чтобы все условия получили одинаковые предъявления; лучший checkpoint выбирается из одинаковых 20 эпох. Каждое завершённое обновление имеет restartable checkpoint с RNG, optimizer, scheduler, порядком и позицией.

## Настройки и нормировка

Pinned RuModernBERT-base revision 8aee6f818db9070b635a549580dc64dcfa03e39a; BF16 frozen base, LoRA rank8/alpha16/dropout0,1, attention Wqkv/Wo. Окна1024, перекрытие128; вся статья, покрытие повторов усредняется. L2 mean по 14 фреймам и индивидуальным ответам. L3 mean BCE по шести семействам и парам внутри каждого непустого ответа, затем mean ответов. Итог статьи L2 + λ L3, затем среднее по статьям; для отдельных моделей оставляется соответствующая часть. L2-пул исходной hidden-размерности; L3-признаки64. Семейства на одной паре multi-label, пересечения и символьные границы сохраняются.

AdamW: LoRA2e-4, головы1e-3, decay0,01, clip1, warmup38/380, линейное снижение. Выбрана общая настройка, уже работавшая в ST1 и E1-base; небольшое преимущество E1-low-lr не переносится автоматически на L2. Нового поиска LR нет. Обучаемые головы и замороженные модули инициализируются в одном порядке во всех условиях. RNG dropout L3-головы изолирован от последовательности dropout энкодера. Одинаковая случайность не предполагает одинаковых градиентов/траекторий.

## Выбор, метрики, критерии

У l2-only и совместных моделей выбирается минимальный dev Brier L2, при равенстве более ранняя эпоха. Единственное выбранное состояние joint оценивается на обоих выходах; отдельный лучший L3 checkpoint joint для улучшения отчётности не выбирается. l3-only выбирается по условному article-mean F1, затем macro-family F1, затем меньшему Brier, затем более ранней эпохе. Для всех дополнительно оценивается последнее состояние epoch20 как сравнение при точно равных выполненных обновлениях. Выбор разных ранних эпох допустим только как одинаковый бюджет выбора, а не одинаковая история выбранных весов.

L2: Brier по индивидуальным ответам, с равным весом статьи и фрейма; macro/micro-F1 при0,5 и строгом большинстве (>половины голосов). L3: условный F1 при собственном dev-пороге из17 значений0,1–0,9 с argmax на заведомо положительных парах; сквозные exact/overlap F1, precision/recall, семейства, доля правильных пустых, число выдач. Автоматический decoder фиксирован для всех: score=logit(p_family)+2×detector_logit, threshold=-5.172313813576109, cap100, без argmax. Дополнительно AP полного списка500×6 и точный оптимальный порог при фиксированном alpha2 **только как заранее назначенная диагностика калибровки**, не критерий выбора joint. На train применяется dev-порог. Охват детектора одинаковый, не приписывается совместному обучению.

До результатов фиксируется рабочий критерий интереса: уменьшение Brier L2 минимум на0,003 относительно нового l2-only, падение условного L3 F1 не более0,02 и сквозного exact-F1 не более0,005 относительно нового l3-only. Это ориентир решения, не статистический тест и не критерий подтверждённого успеха. Лучшее joint определяется по Brier из двух вариантов; все результаты показываются. Парный bootstrap10000 по группам статей на dev — описательный, не учитывает выбор эпох/λ/порогов, обучение на одном seed и многократное использование dev. Исторические лучшие ST1/E1/E3 показываются отдельно: улучшение только слабого нового контроля недостаточно для сильного вывода.

## Проверки и артефакты

Проверить эквивалентность старого L2/E1 forward при одинаковых весах, независимость выходов, градиенты обеих задач в LoRA, градиентную нормировку, символьные границы, точное восстановление после обновления включая следующий update. Затем журнал эпох, checkpoints start/best/last, прогнозы train/dev для best и dev дляlast, ресурс, версии, хэши входов/кода, отчёт по каждому запуску и общий отчёт. Все прежние артефакты ST1/ST2 и исходные данные сохраняются. Проверка свежей загрузки и CPU-пересчёт метрик обязательны. Test не токенизируется, не обучается и не оценивается. ST4 по этому поручению не запускается.

## Профиль перед серией

Техническая проверка заняла10,88с. Совпадение L2/E1 forward при одинаковых весах точное; обе задачи передают ненулевой градиент в LoRA, в чужую голову градиент не проходит. Следующее обновление после восстановления, включая AdamW moments, совпало побитово. Замороженная база не изменилась. Один update на8 выбранных по длине статьях занял1,515с; грубая экстраполяция380updates —575,5с, плюс оценка и ввод-вывод. Peak reserved4,03GiB во время проверки нескольких графов/восстановления. Матрицу20эпох сохраняем; все четыре условия укладываются в предел3600с по этой оценке. Проверка использовала три технических optimizer.step, её веса не используются для обучения.
